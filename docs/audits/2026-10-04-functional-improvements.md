# 功能优化与验收记录

验收日期：2026-10-04。范围为当前 SEC_Monitor 项目及其 Docker 持久化数据。

## 按顺序落地的改动

| 顺序 | 功能 | 结果 |
| --- | --- | --- |
| 1 | 重大事件雷达 | 后端按事件类别统一筛选、排序和分页，包含修订表单；翻页覆盖全部匹配记录。读取失败保留旧列表。 |
| 2 | 内幕交易与 AI 状态 | 共享交易代码和任务状态标签；区分公开市场买卖、其他取得／处置，以及排队、处理中、成功、失败。 |
| 3 | 宏观日历 | BLS 总日历失败后尝试各指标官方日历，最新发布值独立同步；Census 两种日历分别处理；EIA 采用官方 JSON 日历与 CSV 报告周配对，并正确协商 JSON／CSV 请求类型。 |
| 4 | 总览与候选聚合 | 汇总覆盖完整 A/B 候选集合，解决超过 200 条时的截断；健康、概览、效果验证和总览共用短期快照，写入使缓存失效。独立只读聚合并行处理，长价格历史只读取一次，流动性门槛仍采用最近 21 个交易日。总览复用效果验证结果，只为概览前 10 条读取估值历史。技术分析按发行人和事件类型去重读取资本事件。 |
| 5 | 运行状态与调度容量 | API 能力展开项展示实际任务开关、最近状态、下一次执行、覆盖回执和理论轮转容量；健康提示区分正在执行、补偿重试、下次定时执行、未启用、人工核验。美股期货展示自动任务状态。 |
| 6 | 列表与研究工作区 | AI 和评估历史列表采用轻量响应，原始详情和提示词按需读取；研究工作区各模块独立展示、保留成功数据、取消过时请求。候选同步状态轮询在闲置时降频、页面隐藏时暂停。 |
| 7 | IPO 覆盖与解析 | 安全地从 SEC 申报索引页解析同一 accession 下的主文件；解析版本升级后的历史重试限制在每轮 25 条。页面展示失败原因、样本来源、索引页数量和未确认身份，不推测价格、发行股数或股票映射。 |
| 8 | 维护与持久化 | 拆分评估处理器、宏观解析、运行恢复、容量诊断和前端加载模块；新增只读数据库检查命令，输出索引和真实查询计划。保留财务历史及身份唯一索引，现有恢复点策略保持 3 组完整配对。 |

研究分配等写操作继续使用实时服务端门槛，不采用页面汇总缓存作为授权依据。任务开关与供应商调用预算沿用现有配置。

## 实际数据验收

- 35 个本地接口均成功响应；15 个部署后的桌面／移动页面未发现脚本错误、失败请求或写操作。
- AI 列表 5 条由 112,876 字节降至 4,199 字节，减少约 96.3%。评估历史 5 条由 286,848 字节降至 50,234 字节，减少约 82.5%。逐条读取验证原始详情、评估结果和提示词仍完整。
- 总览性能以本地接口 10 次强制重算和 10 次缓存请求验收；最终结果见下表。强制重算同时绕过候选共享快照，避免用暖缓存冒充冷加载。

| 请求方式 | 次数 | P50 | P95 |
| --- | ---: | ---: | ---: |
| 强制重算 | 10 | 1604 ms | 3184 ms |
| 缓存请求 | 10 | 1 ms | 3 ms |

原基线强制重算 P50 为 2,717 ms（5 次），本轮为 1,604 ms（10 次），改善约 41%。冷重算仍略高于原建议的 1,500 ms 目标；首次重算还包含运行健康报告构建，P95 为 3,184 ms。缓存请求达到预期。

## 宏观来源与数据口径

EIA 已读取 2026-09-25 报告周、2026-09-30 发布的最新库存报告，并保存 66 条未来官方日历。下一次发布为 2026-10-07 14:30 UTC，节假日后的一次为 2026-10-15 16:00 UTC；这些时间来自官方日历，不按固定星期推算。

库存水平的前期值采用当前官方 CSV 的对应报告周列，避免旧本地快照替代该值。周变动保持“本期水平减去该前期水平”的计算口径。重复相同报告不会重复写入，已有不一致前期值可在同步时修复。

来源：[EIA 官方发布日历](https://www.eia.gov/petroleum/supply/weekly/includes/wpsr-calendar.json)、[EIA Table 4 CSV](https://ir.eia.gov/wpsr/table4.csv)。

BLS 和 Census 在当前运行环境中仍返回 HTTP 403。回退、独立同步和诊断已落地，但未来官方日历覆盖仍受来源访问限制影响；页面保留该事实，不填入推测日期。历史任务执行记录保留当时的告警。

## 定时更新为何仍可能超出复核期限

当前候选轮转范围为 578 只。每轮 EPS 标的预算为 5、估值预算为 3，理论至少需要 116 和 193 轮才能覆盖一遍，超过 168 小时研究复核窗口。因此，“任务已启用且有成功执行”仍可能同时存在旧数据。实际失败、无覆盖、限流和手动刷新缓存也会影响轮转。

容量展示按真实任务范围和 cron 计算；理论下限假设每轮预算用满且全部成功。“缺少成功回执”也不等于“未同步”：历史记录可能早于覆盖回执机制，查询成功但无数据覆盖也可形成回执。24 小时手动刷新缓存与 168 小时研究复核窗口是不同口径。

## IPO 与存储边界

验收时有 38 条无法完整解析的 424B4 记录：19 条未识别最终发行价、19 条未识别发行股数，其中 8 条原始 URL 是 SEC 索引页。主文件选择问题已修复，历史记录将在后续受限重试中重新处理；其他不支持的格式继续展示原因。

研究数据库保留 3,869,485 条财务事实。实际查询计划确认利润历史和估值查询使用复合索引，增量重算与身份查询使用 security_id 索引。保留这些有实际用途的索引及身份唯一约束，避免仅凭索引前缀相同就删除。

可在当前项目部署中只读检查：

```sh
docker exec sec-monitor /app/storage-maintenance -action inspect
```
