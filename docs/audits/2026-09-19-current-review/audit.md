# SEC Monitor 当前版本复核（2026-09-19）

## 结论

核心研究数据、候选全集与桌面/移动端响应式布局已经可用，Dashboard 缓存命中也很快；当前最值得继续优化的不是增加页面，而是统一“能否交易”的口径、缩小故障影响范围、压缩运行健康查询，以及清洗公告与宏观事件的语义。

## 走查步骤与健康度

1. **今日决策（桌面）— 需优先修正**
   - 市场、候选和新鲜度信息清晰，能看到 75 个可行动、59 个仅研究、7 个阻断候选。
   - 同屏却因 `ipo_radar_sync` 失败显示“当日数据不可用于交易判断 / 新交易计划受限”。IPO 雷达故障与小盘候选行情、基本面和策略有效性不是同一个证据域，当前全局阻断范围过大。
   - 错误横幅仍暴露任务名、SEC URL、英文超时堆栈和 UTC 时间，且在移动端占据一屏以上。
   - 证据：`02-dashboard-desktop-viewport.png`。

2. **策略观察池 — 基础健康，交易语义有冲突**
   - 市场环境、行业强弱、候选门槛和交易纪律已能在一个页面复核。
   - “可行动”目前只代表研究证据门槛通过；同一行仍可能出现“计划失效”或“离场预警”。例如 RNXT、LPTH、CMCO 会让交易员误解为可以新开仓。
   - 宏观事件存在重复 FOMC 记录及 `N ews` 标题污染，重要性全部为“常规”，不利于盘前排序。
   - 证据：`03-strategy-pool.png`。

3. **系统健康 — 信息完整，但首屏可信度和性能仍可提高**
   - 已经能把数据源、备份、调度和恢复演练集中展示，处理入口明确。
   - 初次进入时会短暂显示 `0/0`、`0 B` 和“暂无处理项”，随后才切换到真实值，容易造成健康状态闪烁误判；应使用骨架屏或保留上次成功快照。
   - 当前页面并行请求 5 个接口；实测 `/api/operational-health` 约 1.32 秒、`/api/price-action-cycle/health` 约 0.80 秒，首屏取决于最慢接口。
   - 同一故障既以原始错误卡片出现，又以业务化“调度任务失败”出现；SEC EDGAR 同时显示“正常”，但全局状态为严重，需要明确“常规 SEC 正常、IPO EFFECT 抓取异常”的作用域。
   - 证据：`04-system-health.png`、`04-system-health-loaded.png`。

4. **SEC 公告 — 可检索，事件覆盖仍不足**
   - 8-K 已能展示 Item、事实类型和下一步阅读建议，原文入口明确。
   - Form 4、Form 144、Form 425 仍大量落入“其他公告 / 尚未建立规则”；其中 Form 4 本应直接关联内幕买卖类型、角色、数量与金额，Form 144 应提示潜在减持，425 应关联并购事件。
   - 页面仍混用 `Select`、`Ticker`、`Filing Date` 等中英文标签；表格信息密度高，关键的“事件与论点影响”列在常见桌面宽度下不易看到。
   - 证据：`05-sec-filings.png`。

5. **今日决策（移动端）— 布局健康，异常信息不适合移动阅读**
   - 导航抽屉、按钮和标签页已正常重排，没有明显横向遮挡。
   - 原始异常文本把核心决策区推到首屏以下；长 URL、任务名和英文错误不应成为交易员移动端的主信息。
   - 淡红文字叠加浅红背景存在对比度风险；截图不能证明完整 WCAG 合规，仍需键盘、焦点顺序、屏幕阅读器和 200% 缩放测试。
   - 证据：`06-dashboard-mobile-loaded.png`。

## 建议优先级

### P0：统一交易门控与故障作用域

1. 将运行异常映射到证据域：`market`、`candidate_fundamental`、`candidate_price`、`strategy_validation`、`sec_watchlist`、`ipo`、`notification`。
2. 只有影响当前候选所依赖证据域的 critical 才阻断研究或新计划；`ipo_radar_sync` 只降低 IPO 模块健康度，不应全局阻断普通候选。
3. 把“可行动”拆成“研究就绪”和“交易计划状态”；新开仓候选必须同时满足研究就绪、行情新鲜、计划有效且无离场预警。

### P1：运行健康缓存、聚合与稳定首屏

1. 为 OperationalReport 和价格周期健康增加 30–60 秒进程内缓存，并在相关任务完成后主动失效。
2. 提供聚合的 `/api/system-health/summary`，一次返回首屏指标、业务化问题和快照时间；详细表格延迟加载。
3. 页面加载中显示骨架或“读取中”，不要用 0 充当尚未加载的数据；部分接口失败时保留其他模块并显示各自错误。
4. 当前 Dashboard 强制刷新约 3.23 秒、缓存命中约 1.7 毫秒，缓存有效；下一步应避免持锁执行整个冷查询，改为 singleflight + 锁外构建，防止一个慢刷新阻塞所有缓存读取。

### P1：错误摘要与处置体验

1. 默认仅显示“IPO EFFECT 抓取连续失败 5 次，普通 SEC 公告同步正常，系统将在 HH:mm 重试”。
2. 原始 URL、内部任务名、trace 和 provider 错误移入“技术详情”折叠区。
3. 合并同源故障、失败与过期提醒，避免一个根因生成多张卡片；处置按钮直接带入对应任务和筛选条件。

### P2：事件数据清洗与 SEC 规则覆盖

1. 宏观事件按来源 ID + 发布时间 + 标准化名称去重，修复 `N ews` 等抓取噪声，并为 FOMC/CPI/PCE/NFP 设置可靠重要性。
2. 增加 Form 4、144、425 的结构化规则；Form 4 优先复用内幕交易解析结果，避免在公告页显示“其他公告”。
3. 完成中文界面剩余英文标签，并允许固定“事件与论点影响”列或提供紧凑卡片模式。

## 证据限制
