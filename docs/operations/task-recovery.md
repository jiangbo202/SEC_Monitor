# 任务状态与自动补偿

- 常规定时保留原有 Cron。硬失败会写入 `retry_not_before`；可续跑的日线、研究请求及财报任务也可记录 `pending_count` 并进入补偿队列。数量未知用 null，不伪造为零。
- 每分钟扫描到期队列，使用数据库条件更新认领任务，复用任务互斥与 SEC 资源锁；同一调度实例只有一个补偿扫描器运行。当前部署仍是单应用实例，不承诺分布式多实例调度。
- 每轮常规/手动执行后最多追加 3 次自动重试；成功清零，超限保留错误和缺口，等待常规定时或手动执行开启新一轮。失败退避根据连续失败次数为 5 分钟、15 分钟、1 小时、6 小时、最长 24 小时；部分完成按本轮尝试次数退避，不增加硬失败计数。
- 到期时间是最早可执行时间，检查粒度约一分钟；任务或共享 SEC 资源占用时延后，不消耗重试次数。停用任务不会被补偿扫描器运行。
- 自动重试最多运行两小时；业务网络请求仍使用各自更短的超时。取消/超时后使用独立的 15 秒收尾上下文保存结果，避免界面长期停在“运行中”。进程重启会将中断任务重新排入队列，保留已消耗的次数。
- 日线只补指定交易日有效价格缺口，覆盖计数以落库后有效的不同标的为准；Longbridge 研究复用共享新鲜度/每标的缓存。普通无覆盖提示不等于失败，不启动额外重试。
- 财报日历每页成功后保存窗口、下一日期和已读事件；同窗口未完成扫描可跨进程继续。到新日期或变更窗口后重新扫描。分页游标停滞是未完成，不是完整覆盖。补偿期间跳过当天已成功保存的监控标的财报记录。
- 调度页分别呈现失败/中断、部分完成、运行中和未验证；执行历史用 `retry` 标注自动补偿。已有旧 partial 记录不推断缺口数，下一次任务执行后填入结构化状态。
