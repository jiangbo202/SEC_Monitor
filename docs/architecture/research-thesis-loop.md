# 研究观点闭环与浏览器回归

## 使用入口

在「标的研究」输入 Ticker，或从「监控标的 / 小盘候选」进入研究台。观点独立于基本面评分、技术信号及交易决策/成交台账：保存观点不会改分、交易、调用 AI 或发送通知。

1. 建立草稿：记录研究理由、拟验证事项和失效条件。
2. 关联证据：选择本地 SEC 公告、Form 4 交易、成功的 AI 研判或站内通知。AI 明确标记为非原始事实。
3. 开始跟踪：至少关联一条证据，并填写理由、失效条件、下次验证事项、未来复核时间及本次复核结论。
4. 复核：研究台列出到期观点；进入标的后提示上次复核以来的新入库证据。新信息不会自动改写观点，需人工判断维持、修订或失效。
5. 结束：失效或归档时必须写下复核结论。结束观点须先保存为草稿才能再次激活；原来的失败/结束记录仍留在历史中。

「刷新观点」只读取本地记录，编辑期间禁用。切换标的/页面时有未保存提示；浏览器强制刷新/关闭不保证恢复未保存输入，请及时保存草稿。

## 数据契约

- 主库 `research_theses`：每个 ticker 一个当前观点，`version` 乐观并发控制。
- 主库 `research_thesis_revisions`：每次修订的完整不可变快照，和观点更新、操作审计在同一事务中提交。
- 同一版本不能覆盖较新版本；API 返回 HTTP 409，界面保留输入并要求重新加载、人工合并。
- 保存证据时服务端按类型、ID、ticker 校验归属；不信任客户端摘要和 URL。
- 证据保存来源类型、ID、标签、摘要、链接、入库时间和这些字段的 SHA-256。此校验值不是 SEC 原始文件全文哈希。
- 已关联证据再次修订时沿用保存时的快照；原始记录被清理后，已有观点及修订历史仍可回看。
- 历史库保留全部版本；当前 UI 展示最近 50 版。证据选择器每类最近 20 条，单观点最多 30 条；到期队列最多显示最早的 100 项。
- 新证据数量统计跟踪中观点上次复核后的入库记录，不受选择器 20 条上限影响；同一事件在公告、交易、通知中可有多个证据记录，不等于独立事件数量。
- 来源故障单独标注，不能把读取失败说成「没有观点 / 没有证据」。SQLite 时间比较先标准化时区，避免 UTC/本地文本排序误差。
- 不进行外部抓取或隐式补数据；机构持仓、技术数据等仍沿用研究台原有模块，不自动拼接为人工观点。

### API

| 路由 | 用途 |
| --- | --- |
| GET `/api/research-theses` | 到期的跟踪中观点（最多 100 项） |
| GET `/api/research-theses/:ticker` | 当前观点、复核标志、最近 50 版历史 |
| GET `/api/research-theses/:ticker/sources` | 本地证据选项、新入库计数、不可用来源 |
| PUT `/api/research-theses/:ticker` | 按提交版本保存一次修订 |

没有删除历史、自动确认观点或自动交易接口。

## 回归运行

```sh
go test ./...
cd web
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

`playwright.config.mjs` 启动 `internal/testfixture/browser`：仅监听 `127.0.0.1:19090`，使用内存 SQLite 和真实观点 API 处理器；其他读取使用固定夹具。不会打开当前 Docker 的数据库、代理到 9090、创建调度器、初始化行情/SEC/AI/Telegram 客户端。

手工验收同一夹具可在 `web` 下运行 `GOTOOLCHAIN=auto npm run test:browser:fixture`。此命令只用于开发测试，不能作为正式服务部署。测试控制路由 `/__test/*` 不存在于正式 API Router。关闭进程即丢弃全部测试记录。

测试使用公开 DOM 操作；`tests/browser/scenarios.mjs` 同时供 Playwright CI 和应用内浏览器验收使用。CI 会阻止并报告任何非夹具来源请求、任何未预期 API，保存失败截图与 trace（7 天）。这是代码回归检查，不是生产任务调度。

当前覆盖 8 个流程：

- 本地快照回退、输入框编辑不改变当前标的、站内通知同页跳转。
- 单模块故障时保留其他模块数据。
- 草稿、跟踪、失效、归档和修订历史。
- 缺少证据/验证事项时拒绝激活。
- 到期队列及新证据提示。
- 读取失败不误建新观点。
- 未保存修改的页面离开保护。
- 两个窗口竞争保存时的版本冲突保护。

这些是核心流程回归，不等于所有页面的视觉全覆盖；正式 Docker 部署后仍需只读检查真实数据页。测试工具配置依据 [Playwright Web Server](https://playwright.dev/docs/test-webserver) 与 [CI 文档](https://playwright.dev/docs/ci-intro)。
