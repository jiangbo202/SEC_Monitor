# 小盘股候选：投资研究能力升级需求

日期：2026-07-17
状态：实施中（P0、P1 与 P2 首版已交付）
关联：`2026-07-11-small-cap-candidate-third-batch-design.md`

## 1. 定位与问题

现有“小盘股候选”已经具备 SEC、财务、Form 4、融资风险、日线价格、技术信号、候选关注与通知闭环。它应继续定位为**研究优先级与证据系统**，而不是收益预测器、买卖建议或自动交易系统。

本次升级解决以下问题：

1. 数据缺失或供应商异常时，列表仍可能给人“精确排名”的错觉。
2. 现有评分为离散阶梯分，且同一套收入规则会误读生物医药等行业的一次性收入。
3. 现有效果评估以每个证券的首次入选为样本，无法完整评价再次入选、升级、退出等信号；基准数据缺失时也无法判断相对收益。
4. 候选具备“基本面改善”证据，但缺少估值、预期差和可执行研究备忘录，不能形成完整投资决策材料。

## 2. 目标与非目标

### 目标

- 让用户一眼区分“数据完整、可排序的研究候选”和“仅供补充研究、不可用于排名的候选”。
- 将基础评分从简单的资格加总升级为可解释、可版本化、可按行业校准的研究评分。
- 用无前视偏差、可复现的事件 cohort 验证候选信号，并展示相对基准表现与风险。
- 在不引入自动交易的前提下，补齐估值、催化剂、论点和风险管理信息。

### 非目标

- 不生成“买入/卖出”指令、目标价或自动下单。
- 不承诺策略收益，也不以历史回测结果作为投资建议。
- P0/P1 不接入付费一致预期、券商持仓或实时 Level 2 行情；如以后接入，必须独立配置数据授权与来源披露。
- 不改变现有 SEC 监控、IPO 监控和通知的既有行为，除非本需求明确说明。

## 3. 当前基线与产品原则

### 当前基线

- 候选筛选：市值 30M–1B USD；A 级要求市值低于 500M、收入增长、12 个月现金 runway、近 180 日合格内幕买入且无风险阻断；B 级要求收入增长、赛道评分和无 B 级阻断。
- 基础总分：收入增长 30、现金 20、内幕 20、毛利率 10、稀释风险 10、赛道 10。
- 市场数据使用可配置的 Tiingo / Twelve Data / Yahoo / Stooq 链；价格批次有覆盖率与回退保护。
- 技术指标使用本地日线，仅用于研究筛选，不改变基础评分或候选等级。

### 产品原则

1. **证据优先**：每个展示指标必须能定位到数据来源、有效日和计算方式。
2. **不以缺失替代负面**：缺数据是数据状态，不等于公司质量差；评分、排序和页面标识必须区分两者。
3. **点时一致**：历史回测只能使用信号当日可得的价格、财务和事件，禁止用后续数据改写历史结论。
4. **行业可比优先于通用分数**：对商业模式差异显著的行业，不能只以同一收入增长阈值判断。
5. **人工研究保留最终判断**：系统给出证据、风险与排序；用户负责论点、估值判断和仓位决策。

## 4. P0：数据可信度、行业校准与可验证回测

### P0-1 数据充分性闸门（Data Readiness Gate）

实施状态：核心查询、默认推荐、候选通知、健康统计和页面筛选已于 2026-07-17 交付；Form 4 逐标的覆盖快照、健康统计和详情证据卡已于 2026-07-18 交付。跨批次 readiness 状态变更快照与可配置时效窗口将在后续迭代补齐。

#### 功能

为每个候选生成独立于 A/B 的 `research_readiness`：

| 状态 | 条件 | 列表与排序行为 |
| --- | --- | --- |
| `ready` | 财务、股本/市值、资本风险和最近已收盘交易日价格均有效；对应数据源同步成功 | 正常参与默认推荐、优先级排序和通知 |
| `research_only` | 关键数据的时效、覆盖或解析可信度不足，但尚无明确负面证据 | 保留在完整研究池；默认推荐中降级并不参与“高优先级”筛选 |
| `blocked` | 市场价格或财务证据不可用、资本风险解析失败、或批次未满足发布质量门槛 | 不进入推荐和通知；仅保留审计/排障视图 |

具体规则：

- 财务时效：最新 10-Q/10-K 对应财报期必须在可配置窗口内。默认季度 190 天、年度 400 天；超期为 `research_only`。
- 市值：必须有有效价格、有效股本快照和一致的价格日期；任一缺失不得显示为可排名市值。
- 内幕交易：区分 `covered_no_filings`、`covered_no_transactions`、`covered_transactions`、`partial` 和 `unavailable`。没有合格买入只影响内幕分；来源失败或覆盖未知才影响 readiness。每个安全宇宙批次保存已检查 Form 4 数、下载/解析数及永久缺失、暂时失败、格式异常数；不再把“没有行”直接解释为“没有内幕活动”。
- 风险文件：资本事件源无法解析、或关键 filing 尚未完成处理时，不能以“无阻断风险”代替未知状态。
- 全局健康页新增“候选可排序数 / 仅研究数 / 阻断数”，并列出触发原因与涉及 ticker 数。

#### 页面与 API

- `CandidateScore` 新增 `research_readiness`、`readiness_reasons`、`financial_staleness_days`、`insider_evidence_status`。
- 小盘候选表新增“研究状态”标签和悬浮明细；默认推荐仅显示 `ready`。
- 详情页新增“数据证据状态”卡片，展示各源有效日、同步批次、状态和降级原因。
- 候选通知仅包含 `ready` 候选；若当天 `ready` 数量异常下降，发送/记录一条系统健康提醒，不把它伪装成投资信号。

#### 验收标准

- 模拟财务过期、价格缺失、Form 4 源失败和资本风险解析失败时，状态与原因均正确，并且不会获得“无风险/可排名”表述。
- 同一候选在数据恢复后自动从 `research_only` 恢复为 `ready`，保留历史状态变更。
- 任一 readiness 状态与明细可由 API 和导出 CSV 获取。

### P0-2 行业校准：生物医药优先

实施状态：核心规则、审计型人工确认接口与详情页编辑器已于 2026-07-17 交付。业务模型的确认会在下一次小盘工作流中以 `small-cap-discovery-score-v2-biotech-calibrated` 重算；旧批次保持旧分数但会显示当前确认状态。过期分类的独立待复查队列待后续迭代补齐。

#### 功能

首期仅对“生物医药”建立独立研究规则，其他行业仍使用通用 v1/v2 规则。新增 `business_model`：`commercial`、`clinical_pre_revenue`、`mixed_or_licensing`、`unknown`，初始由人工确认，可保留来源与备注。

- `commercial`：可按收入、毛利、现金 runway 和稀释风险进行通用评分。
- `clinical_pre_revenue`：不因一次性合作/里程碑收入获得完整收入增长高分；收入分上限为 10，默认不进入 A 级。
- `mixed_or_licensing`：收入增长标注“可能含授权/里程碑”，必须人工确认收入可重复性后才可解除上限。
- `unknown`：保守按 `research_only` 处理，不允许以收入增长进入默认主推荐。

人工确认表必须保存：ticker、模型分类、结论、依据文件链接/附件说明、确认人、确认时间、失效/复查日期。

#### 验收标准

- 同样 100% 季度增长的商业化公司与临床前公司不再获得相同收入信号解释。
- 详情和导出能显示业务模型、确认来源、收入分上限及其原因。
- 手工分类不会被每日 SEC 同步覆盖；过期分类会进入待复查队列。

### P0-3 事件化、无前视偏差的效果评估

实施状态：`entered_a`、`entered_b`、`upgraded_quality` 的不可变信号事件、事件当日价格基线、幂等发布写入和效果评估的事件优先读取已于 2026-07-17 交付。旧历史没有事件时，页面明确标为 `legacy_first_entry` 兼容回溯，不能被误解为无前视评估。`readiness_restored` / `exited_recommendation`、20 个交易日跨批次去重、XBI 行业基准与更多分组将在后续迭代补齐。

#### 功能

将“每只股票首次入选”替换为不可变的 `candidate_signal_events`：

- 事件类型：`entered_a`、`entered_b`、`upgraded_quality`、`readiness_restored`、`exited_recommendation`。
- 仅在状态真实变化时生成；同一 ticker、同一规则版本、同类事件默认 20 个交易日内去重。
- 事件基准价取事件当日或之后第一个有效收盘价，保存价格源和日期；不得回填为事件前价格。
- 评价窗口：1、5、20、60 个交易日；报告平均/中位回报、胜率、最大回撤、样本数、基准回报、超额回报和数据成熟度。
- 基准：默认 IWM；生物医药 cohort 同时支持 XBI。基准使用同一价格链入库，缺失时明确显示“无法计算相对收益”。
- 报告按 A/B、质量分层、行业、readiness、事件类型、评分版本分组；样本少于 30 时标记“样本不足，不作结论”。

#### 验收标准

- 重复运行评估不会重复创建相同事件。
- 候选退出后仍保留历史事件和后续回报，不存在仅保留赢家的幸存者偏差。
- 修改当前候选评分不会改变已落库事件的当日评分和基准价。
- 无 IWM/XBI 数据时，报告可用但不得显示虚假的超额收益。

### P0-4 可交易性闸门与价格质量

实施状态：首版已于 2026-07-18 交付。它使用同一价格提供商、且不晚于候选价格日的本地日线，计算样本天数、平均日成交额和波动率；按日成交额给出仅用于研究容量审阅的 5% ADV 日名义额参考。免费日线无法覆盖点差、借券、盘中停牌或盘口深度，页面必须明确提示用户自行核验。

- `tradable`：价格有效，至少 15 个同源日线样本，平均日成交额不少于 $500K，且无已知反向拆股/持续经营风险。
- `constrained`：价格低于 $1、样本不足、平均日成交额在 $100K–$500K 或极端日波动；保留为研究对象，但默认改为 `research_only`。
- `blocked`：价格/日期或流动性历史缺失、平均日成交额低于 $100K，或存在反向拆股/持续经营风险；不参与默认排序与通知。
- 不改变 A/B 基础评分；这是“研究可执行性”而非公司质量或交易建议。

### P0-5 收入、现金与稀释质量

实施状态：收入、现金语义及跨期股本稀释趋势首版均已于 2026-07-18 交付。

- 收入质量除最新季度收入低于 $5M、同比增幅超过 200% 外，新增“去年同期基数低于 $1M”“高同比增长未获环比确认”“季度增长与年度增长方向冲突”提示。它们不篡改原始 SEC 数值，但会在增长公式悬浮说明和详情风险中显式展示。
- 当 TTM CFO/FCF 没有现金消耗时，`999` 仅为 JSON 安全的内部哨兵；页面显示“经营现金流为正，runway 不适用”，并在 runway 排序中按 60 个月封顶，不再把它当作字面意义的 999 个月。
- 现金 runway 继续使用可用现金及短投除以 CFO/FCF 中更保守的月消耗；缺任何关键事实时为不可用，不以 0 或无限大替代。
- 每次安全宇宙同步会从 SEC companyfacts 补充历史封面页已发行股数，比较至少相隔 90 日且在当时已被 SEC 接收的两个快照。股数增加 10% / 25% 分别标注“稀释偏高”/“高稀释”；后者将候选降为 `research_only`。历史不足必须显示“资料不足”，不可以解释为无稀释。
- 该趋势不是 fully diluted share count，也不独立推断发行或拆股；拆股、ATM、认股权证等仍须同时查看融资/稀释风险公告。

## 5. P1：估值、预期差与技术研究升级

### P1-1 估值快照

实施状态：首版已于 2026-07-17 交付到候选完整列表与详情页：市值、现金及短投、完整债务证据下的 EV、TTM 收入/毛利、EV/Sales、EV/Gross Profit、P/S、净现金/市值以及证据日期/缺失原因。只在有连续四个季度和完整流动/非流动债务事实时计算相关倍数；否则为 `N/A`。完整列表支持 EV/Sales 排序、EV/Sales 上限和净现金/市值下限筛选；缺失估值证据始终排在已测量标的之后。跨批次持久化估值趋势仍在后续迭代。

仅基于现有价格和 SEC 财务事实计算，不引入估值目标价：

- 市值、净现金、总债务、企业价值（EV）。
- TTM 收入、TTM 毛利、EV/Sales、EV/Gross Profit、P/S、净现金/市值。
- 每个字段显示财务期末、价格日、股本日和公式；不适用、负值或证据不足时显示 `N/A`，不参与排序。
- 列表支持按 EV/Sales、净现金/市值筛选和排序；详情显示估值趋势与历史快照。

### P1-2 “预期差”研究卡，而非虚假一致预期

实施状态：首版已于 2026-07-18 交付。候选关注记录和候选详情支持维护“市场当前担忧”“可证伪判断”“下个催化剂”“催化剂来源”“预计验证日期”，并明确标注为用户论点；SEC/财务/融资风险等系统事实仍单独展示。催化剂事件的自动提取、来源强制校验和论点版本历史将在后续迭代补齐。

免费公开数据不足以可靠获得全市场分析师一致预期。因此首期不声称“Beat/Miss consensus”。改为可审计的预期差代理：

- SEC 8-K / 财报材料中可提取到的业绩指引上调、首次盈利、重大客户、融资、临床/监管节点。
- 用户可在候选关注记录中录入“市场当前担忧”“我的可证伪判断”“下个催化剂”“预计验证日期”，每项必须有来源或备注。
- 系统将事实事件与手工论点并列展示，不能把手工判断写成数据事实。

### P1-3 中期技术研究

实施状态：MA200 与相对 IWM 的 20/60 日本地匹配交易日强弱已于 2026-07-18 交付；技术详情和图表会在历史足够时显示 MA200，缺少 200 日历史或 IWM 基准时明确显示不可用。用户手动技术历史回填默认请求 320 个自然日（约 220 个交易日）；每日自动预热也会对新进入或历史不足的 A/B 候选补齐同等窗口，但已具备 200 个交易日记录的标的不会重复请求历史接口。候选详情还会以最近一次可审计的“进入 A/B 候选或质量升级”事件为锚点，显示按日线收盘价×成交量计算的 VWAP 近似和偏离；它不等于盘中 VWAP。所有技术数据仅用于独立研究，不改变基础评分或 A/B。以财报、融资及用户催化剂为锚点的扩展仍在后续迭代。

在现有 MA20、MA50、20 日突破基础上增加：

- MA200（历史足够时）。
- 相对强弱：相对 IWM；生物医药可选相对 XBI；使用 20/60 日相对收益。
- 基于日线的事件锚定 VWAP 近似值：财报日、增发/S-3/ATM 日和用户标记催化剂日；明确标注为“日线近似”，不是盘中 VWAP。
- 价格图可叠加上述指标；技术信号仍不得改写基础总分和 A/B 等级。

## 6. P2：研究备忘录与组合风险工作台

### P2-1 结构化投资备忘录

实施状态：首版已于 2026-07-18 交付。研究卡的论点、市场担忧、可证伪判断、催化剂、风险、失效条件和复查日期每次实质变更均追加不可变版本；候选详情显示最近 20 个版本及作者（当前本地单用户默认为 `local_user`）。完整历史分页、附件与多用户身份集成待后续迭代。

扩展现有候选关注记录，增加：

- 核心论点、预期差、关键催化剂及日期、反方观点、失效条件、估值观察、下次复查。
- 每项保留更新时间、作者和证据链接；历史版本可查看，不可静默覆盖。
- 候选详情显示“事实证据 / 用户论点 / 风险”三栏，避免混淆。

### P2-2 手工研究组合（非交易账户）

实施状态：首版已于 2026-07-18 交付。页面可维护 ticker 的最大研究权重、参考成本、日均成交量参与上限、事件风险和流动性约束，并汇总标的数、上限权重和赛道上限。数据仅保存在本地 SQLite；不连接券商、不读取真实账户、不生成交易指令。基于实际成交/持仓的归因、组合波动率和自动再平衡仍不在范围内。

- 用户可为关注标的填写研究仓位意向、目标最大权重、成本参考价、行业暴露和流动性限制。
- 组合页展示单标的权重、行业集中度、低流动性暴露、事件日风险和候选 readiness 风险。
- 不接入券商下单、不读取真实账户、不生成仓位建议；所有仓位数据由用户手工维护并可导出/删除。

## 7. 数据模型、配置与迁移

新增/扩展的核心实体：

- `candidate_readiness_snapshots`：候选/批次的数据充分性与原因。
- `candidate_business_model_overrides`：行业模型人工确认及审计信息。
- `candidate_signal_events`：点时不可变的候选信号事件及基准价。
- `candidate_valuation_snapshots`：估值字段、公式输入和证据日期。
- `candidate_research_memo_versions`：备忘录版本与证据引用。
- `candidate_research_positions`：用户手工研究仓位。

新增配置均应在系统配置页面可见、可恢复默认、可审计，并可用环境变量覆盖：财务时效窗口、readiness 通知阈值、事件去重交易日、默认基准、biotech 行业规则开关、技术指标窗口。

所有新表使用 SQLite migration；不迁移或重写历史候选分数。评分升级必须以新 `scoring_version` 发布，并允许报告按版本对比。

## 8. 交付顺序

1. **P0-1**：数据充分性闸门与健康/通知联动。
2. **P0-3**：事件表、基准同步与无前视偏差效果评估。
3. **P0-2**：生物医药业务模型人工确认与保守评分上限。
4. **P1-1**：估值快照与详情/筛选。
5. **P1-2 / P1-3**：预期差研究卡和中期技术指标。
6. **P2**：备忘录版本与手工研究组合。

## 9. 发布与测试要求

- 每个 P0 功能必须有 Go 表驱动测试：状态机、过期数据、来源失败、重复事件、基准缺失、点时价格和迁移回滚兼容。
- 前端必须覆盖默认推荐、完整研究池、详情、导出和空状态；所有“未知/缺失”均有可读解释。
- 价格/财务/SEC 的 API 单元测试使用假 HTTP transport，不调用外网。
- 发布前执行 `go test ./...`、`cd web && npm run build`；保留当前批次不被新逻辑覆盖的回归测试。
- 首次发布仅生成新状态与历史评估，不自动发送投资类通知；通知规则需由用户显式开启。
