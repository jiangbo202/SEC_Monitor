# 小盘股发现与研究通知系统需求设计

日期：2026-06-22
状态：待用户评审（v2 风险修订）
所属项目：SEC Monitor

## 1. 产品目标

在现有 SEC Monitor 中增加“小盘股发现”能力，每天扫描符合范围的美国上市公司，从 SEC 公告、结构化财务数据、内幕交易和可选的 Reddit 热度中寻找基本面正在改善、同时不存在明显融资或持续经营风险的小公司。

系统只提供研究候选、证据和通知，不自动交易，不生成买卖指令，也不承诺候选未来收益。

核心输出包括：

- A 级候选：条件严格、数据完整、近期存在明确内部人公开市场买入且没有重大风险。
- B 级候选：增长较好、行业方向经过人工确认，但部分增强条件尚未满足。
- 重大利好与重大利空事件。
- 每个结论对应的原始数值、计算公式、数据日期、SEC accession number 和原文链接。

“每日 0～5 只 A 级、20～50 只 B 级”是产品预期，不是通过放宽规则强行满足的配额。实际数量可以为零或超过预期。

### 1.1 子项目边界

本需求不得作为一个实施计划整体开发，必须按以下顺序拆分，每个子项目独立设计、验收和提交：

1. [证券池、行情与市值数据基础](./2026-06-22-small-cap-data-foundation-design.md)：先验证免费行情是否可用，只输出预筛池，不输出 A/B。
2. [财务、内幕交易、融资风险与评分引擎](./2026-06-22-small-cap-research-engine-design.md)：完成所有 A/B 硬条件后才允许产生正式候选。
3. [候选工作流、页面与通知](./2026-06-22-small-cap-workflow-design.md)：提供研究工作台、审计、通知和运行治理。
4. [Reddit 关注度增强](./2026-06-22-small-cap-social-heat-design.md)：可选且不影响基本面等级。

前一子项目验收通过后才能为后一子项目编写实施计划。不得在风险引擎完成前将“预筛公司”展示为 A/B 候选。

### 1.2 产品、进程与数据库边界

小盘股发现属于 SEC Monitor 同一产品和仓库，但作为独立研究域实现：

- 代码放入独立 `internal/discovery` 边界，不把自动发现逻辑加入现有 watch-target 或 filing service。
- HTTP API、前端、配置入口、审计和 Telegram 继续由现有 SEC Monitor 提供。
- 分析型数据使用独立 SQLite `data/small_cap.db`，配置项为 `SMALL_CAP_DATABASE_DSN`；启用 `LOCAL_DATA_BY_DAY=1` 时对应为 `data/YYYY-MM-DD/small_cap.db`。现有 `data/sec_monitor.db` 保留任务配置、运行摘要、通知批次和操作审计。
- 自动发现公司不会自动创建 `WatchTarget`；用户可以通过明确操作把候选加入人工监控。
- 第一阶段任务仍在 `cmd/server` 进程内运行，但 discovery 全量任务全局最多一个，设置独立超时、内存/批量写入上限，不能阻塞健康检查和普通查询。
- 跨库不使用分布式事务。`small_cap.db` 先原子完成并标记 evaluation batch；主库再用确定性 `event_key` 幂等写入运行摘要和通知。重复投递不能产生重复通知。
- 备份与恢复必须同时包含两个数据库，并验证 batch/event 引用完整性。

只有满足任一条件时才新增同仓库 `cmd/discovery-worker`：连续 5 次全量处理超过 60 分钟、server RSS 超过 4GB、API p95 延迟因任务连续 3 次超过 500ms，或 SQLite 写锁导致普通请求连续 3 次失败。拆 worker 不改变数据库和事件契约。

## 2. 范围

### 2.1 纳入范围

第一期仅纳入同时满足以下条件的证券：

- 在 Nasdaq、NYSE 或 NYSE American 上市。
- 美国经营性公司的普通股。
- SEC CIK、Ticker、交易所能够可靠映射。
- 当前处于正常上市状态，非测试证券。
- 最新可用市值在 30M～1B USD 内；其中 A 级上限为 500M USD。

系统按 CIK 识别公司，以 Ticker 作为展示和行情查询标识。Ticker 变更不创建新公司记录。

### 2.2 排除范围

第一期排除：

- OTC 证券。
- ETF、ETN、共同基金、封闭式基金及其他投资公司产品。
- SPAC、空白支票公司及尚未完成业务合并的壳公司。
- ADR 和其他外国私人发行人。
- 银行、保险和其他无法使用收入/毛利率统一口径评价的金融企业。
- 权证、认股权、优先股、单位证券、可转债和其他非普通股证券。
- 已退市、停止报价或无法建立可靠 CIK 映射的证券。
- 多类别普通股导致公司总股本和单一类别价格无法可靠计算市值的公司，可进入“数据待确认”，但不得进入 A 级。

### 2.3 明确不做

- 自动下单、模拟交易、仓位管理或收益承诺。
- 盘中实时选股；默认使用最近一个有效交易日的收盘价。
- 依赖付费行情、付费分析师一致预期或付费行业数据库。
- 自动判断“分析师预期超预期”。没有稳定、合法、可全市场批量使用的免费一致预期数据时，该指标不自动计算。
- 使用生成式 AI 直接决定评分或候选等级。
- 绕过 Reddit API 政策进行网页抓取。
- PostgreSQL、消息队列或新的后端框架。

## 3. 设计原则

1. **硬条件与评分分离**：候选等级先满足硬条件，再按评分排序；高分不能抵消融资、持续经营或数据缺失等硬风险。
2. **证据优先**：任何指标和事件都必须保存来源、期间、原始值、计算值、置信度和解析版本。
3. **缺失不等于良好**：没有发现融资不等于确认没有融资；关键数据缺失时不得进入 A 级。
4. **批量优先**：全市场基础数据使用 SEC 批量文件，避免逐公司请求造成限流和低效率。
5. **可降级**：行情、Reddit 或可选文本解析失败不能破坏已有 SEC 监控；使用最后成功快照并明确标记为过期。
6. **配置有版本**：每次评分记录所使用的配置版本，历史候选结果可以重放和解释。

## 4. 数据源与免费边界

| 数据 | 默认来源 | 用途 | 约束与降级 |
|---|---|---|---|
| 上市证券目录 | Nasdaq Trader Symbol Directory 的 `nasdaqlisted.txt` 与 `otherlisted.txt` | 交易所、证券类型、测试证券、上市状态 | 官方公开目录；失败时保留上一版本，不基于空目录批量退选 |
| CIK/Ticker/交易所映射 | SEC `company_tickers_exchange.json` 和 submissions 元数据 | 公司主键与 Ticker 历史 | 映射冲突进入待确认，不自动合并 |
| 公告历史 | SEC `submissions.zip`、Submissions API 和 EDGAR Archives | 10-K、10-Q、8-K、Form 4、融资文件和风险事件 | 批量文件每日更新，增量公告沿用当前 SEC Monitor 同步能力 |
| 结构化财务 | SEC `companyfacts.zip`、Company Facts API | 收入、现金、经营现金流、毛利、净利润、股本 | XBRL 标签不统一；必须执行标签优先级、期间归一化和质量校验 |
| 公告正文/XML | SEC EDGAR Archives | Form 4 明细、8-K 合同、ATM、持续经营、反向拆股、权证 | 规则解析只能产生带置信度的事件，不允许无证据强判定 |
| 日线价格 | Stooq 免费日线批量数据 | 最近收盘价与市值估算 | 非 SEC/交易所官方行情且无 SLA；实现可替换 Provider，并支持 CSV 导入降级 |
| 行业分类 | SEC SIC + 本地可配置行业表 | 行业标签与“赛道空间”评分 | 行业空间属于研究判断，必须人工配置和审计 |
| Reddit 热度 | Reddit 官方 OAuth Data API，可选 | 关注度、提及趋势和异常热度 | 默认关闭；需要用户提供合法凭据/访问资格；不可用时不影响基本面评分 |

SEC 官方 API 不需要 API Key，但必须使用明确的 User-Agent、限速、缓存和重试。全量任务优先下载 SEC 夜间批量 ZIP；单公司 API 只用于增量补齐。参考：

- https://www.sec.gov/edgar/sec-api-documentation
- https://www.sec.gov/about/developer-resources
- https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs
- https://stooq.com/db/h/

### 4.1 行情可行性门槛

Stooq 只是待验证的默认候选源，不是已经确认可靠的产品依赖。第一个子项目必须先运行至少 20 个交易日的数据验证；以下条件全部满足后，才能启用自动市值晋级：

- 目标范围证券的有效价格覆盖率不低于 98%。
- 最近交易日价格在下一个交易日 12:00 ET 前可用的比例不低于 95%。
- 随机抽样至少 100 只证券，并覆盖拆股、Ticker 变更、多类别股票和退市案例；与第二公开来源人工核验的价格误差不超过 1%。
- 明确记录数据下载方式、允许的使用边界、符号规则、是否复权和公司行动处理方式。
- 连续 3 个交易日不满足覆盖率或及时率时，自动暂停新晋级并发出数据源告警。

验证失败时，系统保留 Provider 接口和管理员 CSV 导入能力，但不得宣称“全市场每日自动筛选”已经可用。

## 5. 总体处理流程

```text
证券目录同步
    ↓
证券类型过滤与 CIK 映射
    ↓
价格 × 最新可靠流通股数 → 每日市值快照
    ↓
30M～1B 初筛池
    ↓
SEC 财务、Form 4、融资与风险事件解析
    ↓
硬条件判断 + 0～100 基本面评分 + 数据质量评分
    ↓
A / B / 观察 / 排除 / 数据不足
    ↓
候选变更、重大事件、每日摘要通知
```

全市场扫描采用漏斗式处理。证券目录和市值覆盖全部范围内证券；昂贵的公告正文解析只对 30M～1B 初筛池及原有人工 Watch Target 执行。

## 6. 证券池与市值

### 6.1 每日证券池同步

每日创建不可变的证券池快照，记录：

- CIK、Ticker、公司名、交易所、证券类型。
- 是否纳入、排除原因、首次发现日期、最后出现日期。
- 最新收盘价、价格日期、股本、股本日期、市值和数据质量。
- 相比上一日是新增、保留、移出还是数据不足。

公司每天重新计算，市值高于或低于阈值时自动纳入或移出。历史候选记录保留，不因移出而删除。

证券类型过滤必须使用可解释规则，而不是只依赖公司名称关键词：

- Nasdaq Trader 的 ETF、Test Issue、Market Category 等结构化字段优先。
- SEC filer category、SIC、注册地、申报表单和公司名称用于识别投资公司、ADR、SPAC 与金融企业。
- 无法确定证券类型时进入 `insufficient_data`，不得默认当作经营性普通股。
- 分类规则保存版本和命中证据；管理员可以覆盖，但必须进入审计日志。

### 6.2 市值计算

默认公式：

```text
估算市值 = 最近有效交易日收盘价 × 最新可靠普通股流通股数
```

股本标签优先级：

1. `dei:EntityCommonStockSharesOutstanding`。
2. `us-gaap:CommonStockSharesOutstanding`。
3. 经人工确认的覆盖值。

质量规则：

- 价格距离最近交易日超过 3 个交易日：市值过期，不进行新晋级。
- 股本快照超过 150 天：标记过期，不进入 A 级。
- 股本必须来自 10-Q、10-K 或对应修订文件，优先采用文件封面最新日期。
- 多类别股票、拆股后价格与股本日期不一致或数量级异常：进入待确认。
- 不使用稀释后加权平均股数替代期末流通股数。
- 最新 10-Q/10-K 之后出现 8-K、424B5、ATM 使用或其他股本变动事件时，旧股本不得继续作为高置信度市值依据；需更新估算股本或暂停晋级。

阈值包含边界：初筛池 `30M <= market_cap <= 1B`，A 级 `30M <= market_cap < 500M`。

## 7. 财务指标解析

### 7.1 历史范围

首次纳入初筛池时回溯：

- 最近 3 个完整财年。
- 最近 8 个可计算季度。
- 最近 3 年融资工具、权证、拆并股及退市风险相关公告；最近 12 个月其他事件正文。
- Form 4 至少回溯 180 天。

后续只做增量同步，财务重述或修订文件会触发受影响期间重算。

### 7.2 收入

收入标签依次尝试：

1. `RevenueFromContractWithCustomerExcludingAssessedTax`。
2. `Revenues`。
3. `SalesRevenueNet`。
4. 经过配置确认的公司自定义扩展标签。

计算：

```text
季度同比 = (最新单季度收入 / 上年同期单季度收入 - 1) × 100%
年度同比 = (最新完整财年收入 / 上一完整财年收入 - 1) × 100%
```

必须使用可比持续经营口径。10-Q 中的半年或九个月累计值需要减去前期累计值还原单季度；第四季度可用全年减前三季度推导。无法可靠还原时标记缺失，不把累计值当作单季度值。

### 7.2.1 XBRL 事实选择算法

同一指标、期间存在多个 facts 时必须按以下确定性规则选择：

1. 单位必须与指标契约一致；收入/现金使用 USD，股本使用 shares，比例使用 pure。
2. 优先选择最新 accepted time 的 10-Q/A、10-K/A 修订事实；修订文件覆盖同一期间的原事实，但不能覆盖不同期间。
3. 期间结束日必须与财务报告 period of report 一致，允许 7 天自然日容差；超出容差视为不同期间。
4. duration fact 按 75～105 天识别季度、330～400 天识别年度；52/53 周财年通过报告元数据校准，不能硬套自然季度。
5. 优先标准 taxonomy 标签；自定义扩展标签只有在 presentation/calculation linkbase 可映射到目标概念，或人工规则确认后才可采用。
6. 相同优先级仍冲突时标记 `fact_conflict`，不得以最大值、最小值或最后遍历值自动解决。
7. 每个归一化值保存原始 concept、unit、start/end、form、filed、frame、accession number 和解析器版本。

重述、修订或解析器升级必须创建新指标版本并触发受影响评分重算，不可覆盖历史快照。

### 7.2.2 增长质量标记

收入增长同时产生以下风险标记，不直接伪装成增长率调整：

- 最新单季度收入低于 5M USD：`low_revenue_base`。
- 同比增长超过 200%：`extreme_growth_review`。
- 最近 12 个月披露重大收购、资产剥离或终止经营：`comparability_risk`。
- 上年同期收入为零或负数：同比不可计算，不得显示为无限增长。

这些公司可以进入 B 级人工复核，但存在 `comparability_risk` 时不得进入 A 级。

### 7.3 毛利率

```text
毛利 = 收入 - 营业成本
毛利率 = 毛利 / 收入
毛利率同比变化 = 最新季度毛利率 - 上年同期毛利率
```

若公司直接报告 `GrossProfit`，优先与“收入减成本”交叉校验。金融、保险等毛利率不适用行业在第一期排除；其他无法可靠计算的公司该项得 0 并显示“不适用/缺失”，不得虚构为 0% 毛利率。

### 7.4 现金续航

```text
可用现金 = 现金及现金等价物 + 可随时变现的短期投资
经营现金流月均消耗 = max(0, -最近四季度经营现金流合计 / 12)
自由现金流月均消耗 = max(0, -(经营现金流 - 资本开支) / 12)
CFO 续航月数 = 可用现金 / 经营现金流月均消耗
FCF 续航月数 = 可用现金 / 自由现金流月均消耗
```

规则：

- 同时展示 CFO 续航和 FCF 续航；A 级默认使用两者较低值。
- 最近十二个月经营现金流和自由现金流均为正时，显示“现金流为正”，评分按最高档处理，但不显示“无限月”。
- 不把受限现金、长期投资、未使用信贷额度或计划融资计入可用现金。
- 历史不足四季度时允许使用最近两个季度年化，但标记低置信度，不能进入 A 级。
- 未来 12 个月已披露的本金到期额超过可用现金 25% 时产生 `debt_maturity_risk`，阻止进入 A 级，除非存在已承诺且可验证的再融资安排。

### 7.5 首次盈利

“首次盈利”定义为：最新单季度归属于普通股股东的 GAAP 净利润大于 0，且此前连续四个可比季度均小于等于 0。仅 EBITDA 转正、调整后利润转正或单纯经营现金流转正不算首次盈利。

## 8. Form 4 内幕买入

### 8.1 合格买入

合格事件必须同时满足：

- 表单为 Form 4 或 4/A。
- 非衍生证券交易表中的 transaction code 为 `P`。
- acquired/disposed code 为 `A`。
- 角色为 CEO、CFO 或创始人。
- 交易发生在最近 180 天内。
- 成交股数和价格可解析，交易价值大于 0。

明确排除：期权授予或行权、限制性股票归属、薪酬授予、赠与、继承、税务代扣、内部转换，以及 transaction code `A`、`M`、`F`、`G` 等非公开市场买入。

### 8.2 角色识别

- CEO/CFO：优先使用 Form 4 XML 的 officer title，结合可配置同义词规范化。
- 创始人：仅当 officer title 明确包含 Founder/Co-Founder，或本地人工角色表确认时认定。
- 仅为董事、10% 股东或其他高管的公开市场买入仍展示为普通内幕买入，但不满足 A 级的关键角色条件。

修订表单需要关联原交易，避免重复计数。每笔交易保存申报人、角色、直接/间接持有、交易日期、股数、价格、价值、accession number 和原文链接。

内幕买入强度同时计算相对指标：

```text
增持比例 = 最近 180 天合格买入股数 / 买入前持股数
买入市值比例 = 最近 180 天合格买入金额 / 公司市值
```

买入前持股数缺失时只计算绝对金额分，并降低该指标置信度。创始人身份默认只接受人工确认；XML title 明确包含 Founder/Co-Founder 时可自动建议，但仍需保存识别证据。

## 9. 融资、稀释与重大风险

### 9.1 “最近 6 个月没有融资”

本需求采用更严格且唯一的默认口径：A 级候选最近 180 天内没有“已确认股权融资”。原始想法中的 90 天作为可配置值保留，但默认配置为 180 天。

已确认股权融资包括：

- ATM 实际出售股票并取得资金。
- 包销或注册直接发行已经定价/完成。
- PIPE、私募普通股或可转换证券。
- 8-K Item 3.02 披露的未注册证券出售。
- 424B5、招股说明书补充文件或定期报告明确披露已经发行并取得款项。

仅提交 shelf registration、S-1 或 S-3 记为“注册融资风险”，而不是“已确认融资”。普通 shelf 本身只提示；只有确认建立 ATM，或注册文件同时包含明确近期发行条款/高稀释风险时，才默认在 90 天内阻止进入 A 级。

### 9.1.1 融资工具生命周期

首次分析必须回溯至少 3 年，按融资工具建立状态，不以单份文件或关键词代表最终结论：

```text
proposed → registered → active → partially_used → exhausted/expired/withdrawn
```

- 普通 shelf registration 仅记为 `registered`，不因 S-3 本身自动判定 ATM。
- ATM 必须从销售协议、prospectus supplement 或明确文本确认；后续 10-Q/10-K 的已售股数和净所得更新为 `partially_used`。
- 424B5 必须关联具体 registration statement，避免重复计算同一融资。
- 权证保存发行数量、行权价、到期日、已行权和剩余数量；信息不足时不得宣称已经解除。
- 每家公司保存融资覆盖起止日期和完整度。覆盖不足、下载失败或状态冲突时，融资硬条件为 `unknown`，不得进入 A 级。

### 9.2 股本稀释

```text
一年股本变化率 = 最新期末普通股流通股数 / 约一年前可比股本 - 1
三年累计稀释率 = 最新股本 / 三年前可比股本 - 1
```

拆股、合股和股票类别重组必须先做公司行动调整。无法调整时不评分。

### 9.3 风险事件

| 事件 | 默认有效期/解除条件 | 对 A/B 的影响 |
|---|---|---|
| Going Concern Warning | 持续到后续 10-K/10-Q 明确不再存在，最长不自动过期 | 阻止 A 和 B |
| 已确认融资 | 180 天 | 阻止 A；B 显示风险，稀释仍按实际股本变化计分 |
| 新普通 shelf registration | 90 天内提示 | 不单独阻止 A；与 ATM、发行条款或高稀释风险组合时阻止 A |
| ATM 已建立但未确认出售 | 90 天或明确终止 | 阻止 A |
| Reverse Split 提议或完成 | 365 天 | 阻止 A；B 标记高风险 |
| 权证潜在稀释 | 直到到期、行权或后续文件确认余额显著下降 | 潜在稀释超过基本股本 10% 时阻止 A |
| 退市通知/上市资格缺陷 | 直到恢复合规 | 阻止 A 和 B |

风险解析必须区分 `suspected`、`confirmed`、`resolved`。仅关键词命中为 suspected；结构化字段、明确金额/日期或人工确认后才能成为 confirmed。

## 10. 重大利好事件

系统识别并展示以下事件，但不直接篡改基本面评分：

- CEO/CFO/创始人的合格 Form 4 公开市场买入。
- 8-K Item 1.01 中的重大客户合同。
- 首次 GAAP 单季度盈利。
- 公司明确上调收入、利润或现金流指引。
- IPO 后首次发布的可计算 10-Q/10-K。

“重大客户合同”和“上调指引”依靠规则解析时分级：

- 高置信度：存在明确 8-K item、合同方、金额/期限或新旧指引数值。
- 中置信度：文本语义匹配但缺少可验证金额，只提示“可能事件”，不作为 A 级硬条件。
- 低置信度：仅关键词命中，不发送即时强信号通知。

规则解析上线前必须使用固定标注样本评估。高置信度即时通知要求 precision 不低于 90%；无法达到时降级为人工待确认事件。重大合同只有在可以识别合同方，并且识别金额、期限、最低采购承诺之一时才能成为高置信度。指引上调必须同时解析同一指标的新旧区间，不能只匹配“raise/increase”关键词。

“IPO 后首次超预期财报”不自动实现，因为“超预期”需要分析师一致预期。第一期只标记“IPO 后首份财报”及其实际增长/盈利结果。

## 11. 评分模型

基本面评分总分 100，严格保持用户给定权重。评分只用于满足硬条件后的排序。

### 11.1 收入增长：30 分

- 最新季度同比，20 分：负增长 0；0～20% 为 5；20～40% 为 10；40～70% 为 15；大于等于 70% 为 20。
- 最新年度同比，10 分：负增长 0；0～10% 为 2；10～20% 为 4；20～40% 为 7；大于等于 40% 为 10。

### 11.2 现金储备：20 分

- 最近十二个月经营现金流和自由现金流均为正：20。
- CFO/FCF 续航较低值大于等于 24 个月：20。
- 18～24 个月：16。
- 12～18 个月：12。
- 6～12 个月：5。
- 少于 6 个月：0。

### 11.3 内幕增持：20 分

内幕增持分由绝对金额和相对增持各 10 分组成：

- 绝对金额：大于等于 1M USD 为 10；250K～1M 为 8；100K～250K 为 6；25K～100K 为 4；小于 25K 为 2；无买入为 0。
- 相对增持：增持比例大于等于 20% 为 10；10～20% 为 8；5～10% 为 6；2～5% 为 4；0～2% 为 2；不可计算为 0。

多名关键角色分别买入时提高事件优先级，但不额外突破 20 分上限。

### 11.4 毛利率：10 分

- 最新毛利率水平 5 分：按本地行业基准的百分位评分；大于等于 P75 为 5，P50～P75 为 4，P25～P50 为 3，0～P25 为 1，负毛利率为 0。行业样本少于 20 家时该项使用中性 2 分并标记低置信度。
- 同比改善 5 分：改善至少 5 个百分点为 5；2～5 个百分点为 4；0～2 个百分点为 2；下降为 0。

### 11.5 股本稀释历史：10 分

按拆并股调整后的一年股本变化率：不增加或下降为 10；0～3% 为 9；3～5% 为 7；5～10% 为 4；10～20% 为 1；超过 20% 为 0。

### 11.6 赛道空间：10 分

赛道分不能从 SEC 文件客观推导。管理员按“本地行业分类”维护 0～10 分，同一行业内公司默认继承评分；公司级覆盖仅用于特殊情况。行业映射以 SIC 为起点，但必须保存本地行业 ID、评分理由、来源、更新人和更新时间。未评估行业默认 5 分，但不能满足 B 级“优秀赛道”的硬条件；B 级要求人工确认分数大于等于 7。

正式启用 B 级前，必须完成覆盖初筛池至少 90% 公司的行业映射；否则未映射公司只进入 `watch`，并在运行报告中显示行业覆盖缺口。

行业毛利率基准使用当季度预筛池内具备有效可比数据的经营性普通股，按本地行业分组，每季度重算并保存基准版本；不得只用当日 A/B 候选作为样本。

### 11.8 评分校准

v1 分档属于研究启发式规则，不声称已经证明能够预测股价表现。正式开启 A/B 外发通知前必须：

- 对至少 200 家按行业和市值分层抽样的公司执行两年历史重放，检查事实选择、候选数量、行业偏差和风险漏判。
- 运行至少 20 个交易日 shadow mode，只展示结果，不发送普通晋级通知；高风险数据错误告警仍可发送。
- 记录每项分数分布、A/B 数量、人工误判和数据不足原因。
- 不以达到“0～5/20～50”目标数量为由调节阈值。
- 任何分档修改创建新配置版本，并保留新旧版本对同一批次的对比结果。

校准验收关注数据和规则正确性，不以短期股价收益作为上线门槛。

### 11.7 数据质量

另算 0～100 的数据质量分，不计入基本面 100 分：

- 市值与 CIK 映射：25。
- 可比季度和年度收入：25。
- 现金与经营现金流：20。
- 股本与公司行动调整：15。
- Form 4 和融资公告覆盖完整：15。

A 级要求数据质量至少 85，且所有硬条件相关数据均非低置信度。B 级要求至少 70。

## 12. 候选等级

### 12.1 A 级候选

必须同时满足：

- 功能和该公司均处于启用状态。
- 30M <= 市值 < 500M USD。
- 最新季度收入同比 > 40%。
- CFO/FCF 续航较低值 > 12 个月，或最近十二个月经营现金流和自由现金流均为正。
- 最近 180 天没有已确认股权融资。
- 最近 90 天没有未解除的 ATM 建立风险或与明确发行条款组合的注册融资风险。
- 最近 180 天至少一笔 CEO、CFO 或创始人的合格 Form 4 买入。
- 不存在 Going Concern、退市缺陷、反向拆股或重大权证稀释等 A 级阻断事件。
- 基本面评分 >= 70。
- 数据质量分 >= 85。

### 12.2 B 级候选

必须同时满足：

- 30M <= 市值 <= 1B USD。
- 最新季度收入同比 > 20%。
- 人工确认赛道分 >= 7。
- 基本面评分 >= 50。
- 数据质量分 >= 70。
- 不存在 Going Concern、退市缺陷等同时阻断 A/B 的事件。

B 级不强制要求关键内部人买入或 12 个月现金续航，但必须清晰显示缺项与风险。

### 12.3 其他状态

- `watch`：进入 30M～1B 初筛池但未满足 A/B。
- `insufficient_data`：关键数据缺失、过期或冲突。
- `excluded`：证券类型、交易所、市值或重大风险不符合范围。
- `manual_hold`：管理员暂停自动晋级，保留数据更新。

等级按每日快照计算，不覆盖历史。任何人工覆盖都必须记录审计日志。

为防止阈值附近反复升降：

- 页面每天展示最新计算结果，不对研究数据做隐藏式平滑。
- 新晋 A/B、A/B 降级或因市值越界移出，必须连续两个成功日批次得到相同结论后才发送通知。
- Going Concern、已确认融资、退市缺陷等高风险事件不等待两个批次，立即降级并通知。
- 同一公司同一迁移方向默认 7 天通知冷却；高风险事件不受冷却限制。

## 13. Reddit 热度

Reddit 是独立“关注度指标”，不进入第一期 100 分基本面评分，也不能把不合格公司提升为 A/B。

启用后按配置的 subreddit allowlist 收集：

- Ticker 和公司名提及次数。
- 去重作者数、帖子数、评论数、净得分。
- 最近 24 小时相对过去 30 天同星期/时段基线的 z-score。
- 单一作者集中度、重复文本比例和账号年龄等可用反垃圾特征。

输出 `cold`、`normal`、`rising`、`spike`，并标记样本量。低样本、Ticker 与常用英文单词冲突或疑似刷量时不得发送高热度通知。

所有模块必须可独立启停。至少提供：

```text
small_cap.enabled
small_cap.universe.enabled

small_cap.fundamentals.enabled
small_cap.insider.enabled
small_cap.financing.enabled
small_cap.event_detection.enabled
small_cap.reddit.enabled
small_cap.notifications.enabled

small_cap.market_cap_min_usd = 30000000
small_cap.a_market_cap_max_usd = 500000000
small_cap.b_market_cap_max_usd = 1000000000
small_cap.a_revenue_growth_min_pct = 40
small_cap.b_revenue_growth_min_pct = 20
small_cap.a_cash_runway_min_months = 12
small_cap.a_financing_lookback_days = 180
small_cap.a_registration_risk_days = 90
small_cap.insider_lookback_days = 180

```

评分分段、风险有效期、SEC 表单类型、文本规则、同义词和通知策略均可配置。配置修改后只影响下一次计算；重算历史必须由用户明确触发。

配置必须先校验、预览影响，再原子激活。至少保证：

- `market_cap_min < a_market_cap_max <= b_market_cap_max`。
- 分数和数据质量阈值处于 0～100，观察天数为正整数。
- A 级增长阈值不低于 B 级。
- 配置保存生成不可变版本号和内容哈希；评分批次只引用一个已激活版本。
- 激活前显示按最新快照模拟得到的 A/B 数量变化，不直接发送模拟通知。

## 15. 调度与通知

### 15.1 默认任务

- `security_universe_sync`：每日一次，同步上市证券和 CIK 映射。
- `market_price_sync`：每个交易日收盘数据可用后执行。
- `sec_bulk_financial_sync`：SEC 夜间批量文件更新后每日执行。
- `small_cap_score`：上述任务成功后执行，也支持手动立即运行。
- `sec_filing_sync`：沿用现有增量公告任务，对候选池和人工 Watch Target 更新事件。
- `reddit_heat_sync`：启用时每日或每小时执行，受 API 限额控制。

依赖任务失败时评分任务不得用空数据覆盖现有结果。运行记录需区分成功、部分成功、过期数据和失败。

所有业务调度统一使用 `America/New_York`，展示层再转换为用户时区。市场任务使用 NYSE 交易日历；周末和交易所休市日不创建虚假的缺失价格告警。

每次评分创建不可变 `evaluation_batch_id`，并绑定唯一的：

- 证券池版本。
- 价格批次及交易日。
- SEC submissions/companyfacts 批次。
- 解析器版本。
- 配置版本。

任何依赖批次过期、失败或时间不一致时，整个评分批次标记 `partial`，不得产生新晋级通知。任务必须幂等；相同输入版本重复运行产生相同结果且不重复通知。

### 15.2 通知类型

即时通知：

- 新进入 A 级。
- A 级出现合格关键内部人买入、已确认融资、Going Concern、反向拆股或退市风险。
- 已确认重大合同、首次盈利或上调指引。

每日摘要：

- A/B 当前数量与新增、移出、升级、降级。
- 排名前若干候选及分数变化原因。
- 数据源失败、过期或数据不足数量。
- Reddit 热度异常，仅在模块启用时显示。

同一 accession number、同一事件版本和同一等级迁移只能通知一次。首次历史回溯建立静默基线，不发送旧事件洪水；规则与现有 notification batch 机制一致。

## 16. 页面与交互

新增一级页面“小盘股发现”，包括：

1. **A 级**：排名、分数、市值、收入增长、现金续航、关键买入、融资空窗和风险。
2. **B 级**：同上，并突出显示距离 A 级缺少的条件。
3. **全部初筛池**：支持等级、交易所、行业、市值、增长、现金、内幕买入、融资风险和数据质量筛选。
4. **事件流**：按利好/利空、严重度、置信度、表单和日期筛选。
5. **行业评分**：维护赛道分及研究理由。
6. **配置与任务**：启停、阈值、Cron、数据源状态和手动运行。

公司详情必须展示：

- 当前等级及每个硬条件的通过/失败状态。
- 100 分评分拆解和数据质量评分。
- 最近 8 季度收入、增长、毛利率、现金和经营现金流趋势。
- 3 年股本变化。
- Form 4 合格与被排除交易明细，并解释排除原因。
- 融资与风险事件时间线。
- 每个指标的 SEC 原文链接、期间、抓取时间和解析置信度。
- “为什么升级/降级”的快照差异。

## 17. 数据模型边界

在现有模型之外增加独立的小盘股研究域，避免把自动发现公司直接写成人工 Watch Target：

- `security_master`：CIK、Ticker 历史、交易所、证券类型和有效状态。
- `universe_snapshots`：每日纳入/排除与原因。
- `market_price_snapshots`：价格、交易日、来源和质量。
- `share_snapshots`：股本、期间、表单、来源和调整状态。
- `financial_periods`：归一化季度/年度财务指标。
- `insider_transactions`：结构化 Form 4 交易与合格判定。
- `company_events`：融资、合同、盈利、指引和风险事件及生命周期。
- `sector_ratings`：人工行业评分和理由。
- `score_snapshots`：评分拆解、配置版本和数据质量。
- `candidate_snapshots`：等级、硬条件结果和迁移原因。
- `social_heat_snapshots`：可选 Reddit 指标。

研究域表位于独立 `small_cap.db`，仍使用 SQLite 和 GORM migration。现有主库中的 `filings`、`sync_runs`、`notification_batches`、配置、审计日志和 Telegram 服务继续复用；跨库仅通过 batch ID、event key 和来源引用关联，不创建跨库外键。

### 17.1 SQLite 容量与保留

- 全证券每日明细快照保留 90 天，之后按月压缩为月末快照。
- A/B 候选、评分迁移、公司事件、人工覆盖和审计记录长期保留。
- 原始 SEC 文档不重复存入数据库，只保存 accession、URL、哈希和必要解析证据；下载缓存按配置清理。
- 每次批次记录新增行数和数据库增长量；预计未来 12 个月数据库超过 5GB 时发出容量告警。
- 清理任务不得删除重放当前 A/B 结论所需的配置版本、输入引用和证据。

## 18. 异常处理与可观测性

- 下载文件先写临时文件，完成校验和解析后原子替换快照。
- HTTP 429/5xx 使用有上限的指数退避；SEC 请求采用全局限速器。
- 每个 Provider 记录最后成功时间、数据日期、耗时、记录数、校验错误和失败原因。
- 解析器升级保存版本号；相同原始文档可离线重放。
- 单公司解析失败不能中断整批扫描，失败进入逐公司明细。
- 数据异常检测包括负收入、股本数量级突变、重复期间、价格/拆股错配和不可能的增长率。
- 使用过期快照时页面和通知必须显式标记，不得显示为“今日已更新”。
- 日志不得记录 API 凭据、Reddit secret、Telegram token 或其他敏感配置。

## 19. 测试与验收标准

### 19.1 核心验收

1. 系统可从公开证券目录构建符合范围的上市普通股池，并解释每个排除原因。
2. 每日市值变化能使公司自动进入或移出初筛池，历史快照不丢失。
3. 累计季度 XBRL 数据不会被误当作单季度收入或现金流。
4. 只有 Form 4 transaction code `P` 的关键角色公开市场买入满足 A 级内幕条件。
5. 期权、赠与、授予和行权不会误计为公开市场买入。
6. 已确认融资与仅注册融资能被区分，并分别应用 180/90 天规则。
7. Going Concern、Reverse Split、ATM、Warrants 等事件具有证据、置信度和有效状态。
8. A/B 等级完全可由保存的输入、配置版本和公式重算。
9. 关键数据缺失、过期或冲突时不会误升 A 级。
10. 首次回溯不发送历史通知；后续等级迁移和新事件不会重复通知。
11. Reddit 或价格 Provider 失败不影响 SEC 公告同步和现有页面。
12. 所有人工行业评分、事件确认和覆盖值进入操作审计日志。

### 19.2 量化验收

- 参考环境为 Apple Silicon 8 核、16GB RAM、本地 SSD、100Mbps 网络和空闲系统；验收记录实际 CPU、Go 版本、输入批次大小及冷/热缓存状态。
- 完整日批次端到端在 60 分钟内完成；输入已下载时解析与写库不超过 40 分钟；增量 SEC 事件批次 10 分钟内完成。
- server 峰值 RSS 不超过 4GB；全量任务期间健康检查持续成功，普通 API p95 不超过 500ms。
- 行情覆盖率、及时率达到 4.1 的门槛，否则自动晋级保持关闭。
- 初筛池公司 CIK 映射成功率不低于 99%，证券类型明确率不低于 98%。
- 具备标准 XBRL 数据的抽样公司中，季度收入还原与人工核验一致率不低于 98%。
- Form 4 `P` 买入结构化解析 precision/recall 均不低于 99%。
- 已确认融资和 A/B 阻断风险在标注样本上的 precision 不低于 95%、recall 不低于 90%。
- 高置信度重大合同/上调指引通知 precision 不低于 90%。
- 相同输入版本重复评分结果完全一致，重复运行不产生额外通知。
- 正常运行 12 个月的 `small_cap.db` 预计数据量不超过 5GB；超过预算必须先调整快照压缩策略。
- 任何数据源失败都不得将超过 1% 的现有候选错误迁移为 `excluded`；应保持旧等级并标记数据过期。

### 19.3 自动化测试

- Go 服务层使用表驱动测试覆盖边界值、缺失值、修订值和失败降级。
- SEC、Stooq 和 Reddit 测试全部使用 fake client 或自定义 `http.RoundTripper`，不执行真实外部请求。
- 为 XBRL 期间还原、Form 4 XML、融资事件状态机、拆并股调整、评分和候选迁移提供固定样本。
- API 覆盖分页、筛选、排序、配置验证、手动运行和成功/错误响应格式。
- 前端构建必须通过，并覆盖关键等级和风险展示逻辑。
- 交付前执行 `go test ./...`、`npm run build`，Go 总语句覆盖率保持不低于 80%。

## 20. 分阶段交付

### 子项目 1：证券池、行情与市值数据基础

- 证券目录、CIK 映射、价格 Provider 和市值快照。
- 免费行情 20 个交易日可行性验证、CSV 降级和数据源熔断。
- 只输出 30M～1B 的“预筛池”，不得输出正式 A/B。

### 子项目 2：研究与风险评分引擎

- SEC 批量财务归一化及确定性 XBRL 事实选择。
- 收入、双口径现金续航、行业毛利率、股本稀释和 Form 4 `P` 交易。
- 三年融资工具生命周期、已确认融资与注册风险状态机。
- ATM、Going Concern、Reverse Split、Warrants。
- 重大合同、首次盈利、上调指引。
- 行业评分、数据质量、A/B 评分和批次一致性。
- 只有本子项目验收后才能首次生成正式 A/B。

### 子项目 3：候选工作流、页面与通知

- A/B/观察池、公司证据详情、事件确认和配置影响预览。
- 即时通知、每日摘要、迁移防抖、审计和解析重放。
- SQLite 快照压缩、容量监控和运行健康状态。

### 子项目 4：Reddit 关注度增强

- 合规的 Reddit OAuth 接入。
- 热度基线、异常检测和反垃圾规则。
- 不改变基本面等级的关注度展示和通知。

子项目 1～3 构成完整基本面产品；Reddit 永远保持可选，失败时不改变 A/B。

## 21. 成功标准

- 每个 A/B 候选都能在详情页回答“为什么入选、用了哪期数据、源文件在哪里、哪些条件未满足”。
- 每日扫描可以在本地环境稳定完成，不依赖付费数据源。
- 数据源短暂失败不会产生大规模错误晋级、退选或通知风暴。
- 用户可以独立启停每个模块并调整阈值，历史评分仍可按配置版本解释。
- 候选数量由规则和数据决定，而不是为了达到目标数量而修改门槛。
