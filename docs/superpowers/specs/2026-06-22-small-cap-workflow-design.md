# 小盘股候选工作流、页面与通知设计

日期：2026-06-22
状态：待用户评审
依赖：[小盘股研究与风险评分引擎](./2026-06-22-small-cap-research-engine-design.md)
上位规格：[小盘股发现与研究通知系统](./2026-06-22-small-cap-discovery-design.md)

## 1. 目标

把评分引擎输出变成可研究、可审计、不会产生通知风暴的本地工作台。本子项目不改变评分公式，只展示证据、管理人工判断并发送通知。

## 2. 页面

新增“小盘股发现”一级页面：

- A 级、B 级、观察池和数据不足。
- 全部预筛公司及筛选、分页、排序。
- 利好/利空事件流和人工确认队列。
- 本地行业评分与覆盖率。
- 配置版本、影响预览、数据源和任务健康。

公司详情展示硬条件通过/失败、评分拆解、数据质量、8 季度财务趋势、3 年股本、Form 4 明细、融资工具生命周期、风险事件和 SEC 原文证据。

## 3. 等级迁移

页面显示每个成功日批次的真实结果。通知使用防抖：

- 普通晋级、降级或市值移出需连续两个成功日批次结论一致。
- Going Concern、确认融资、退市缺陷等高风险立即降级并通知。
- 同方向迁移默认 7 天冷却，高风险不受冷却限制。
- 每次迁移保存旧等级、新等级、改变的硬条件、评分差异和批次 ID。

## 4. 人工工作流

允许人工维护：

- 证券分类和 CIK/Ticker 冲突。
- 创始人角色。
- 行业映射与赛道分。
- 融资/风险事件确认和解除。
- 市值、股本等有限覆盖值。

所有覆盖必须包含理由，可选来源链接、操作人和时间；覆盖不能改写原始数据，只改变 effective view。清除覆盖后恢复自动结果。

## 5. 配置激活

配置修改先保存草稿并校验，再基于最新成功批次预览：A/B 数量、升级、降级和数据不足变化。用户确认后原子激活新版本；预览不发送通知。

## 6. 通知

即时通知：新晋 A、A 级关键 Form 4 买入、高置信度重大合同/首次盈利/上调指引，以及确认融资、Going Concern、反向拆股、退市风险。

每日摘要：A/B 总数、迁移、排名变化、数据质量缺口、Provider 健康和待人工确认事件。

去重键包含公司、事件类型、事件身份、事件版本和通知策略版本。首次历史回溯建立静默基线；修订文件只有造成有效事件变化时才再次通知。

## 7. 运行健康

- 所有时间以 `America/New_York` 计算，界面按用户时区显示。
- discovery 分析表来自独立 `small_cap.db`；任务配置、运行摘要、通知批次和操作审计写入主库。
- 分析批次先在 `small_cap.db` 完成，再以确定性 `event_key` 幂等投递主库；不存在跨库事务或跨库外键。
- 页面区分成功、部分成功、失败和过期数据。
- partial 批次不能触发普通等级迁移通知。
- 数据源失败时保持上一成功等级并显示过期，不批量标记 excluded。
- 每个任务提供耗时、处理数、失败数、数据日期和批次依赖。
- 全量 discovery 任务运行时，健康检查必须持续成功，普通只读 API p95 延迟不超过 500ms；连续 3 次超过阈值进入拆分 worker 评估。

## 8. SQLite 治理

- 全证券每日快照保留 90 天，之后压缩为月末快照。
- A/B、迁移、事件、配置版本、人工覆盖和审计长期保留。
- 原始 SEC 文档不重复入库，只保存 accession、URL、哈希和解析证据。
- 预计 12 个月数据库超过 5GB 时告警。
- 清理不能破坏当前结论重放。

## 9. API 与权限边界

沿用现有 API 响应、分页、审计和敏感配置掩码约定。研究查询为只读；配置激活、人工确认、覆盖和任务运行属于写操作并记录 operator。

不在 API 中返回 Reddit secret、Telegram token 或 SEC User-Agent 中可能包含的敏感联系方式。

## 10. 验收

- 每个 A/B 能解释所有硬条件、输入期间、配置和 SEC 证据。
- 两次确认防抖、高风险立即降级和 7 天冷却行为正确。
- 首次回溯、重复批次和同一事件修订不会产生通知洪水。
- 配置预览与激活后首个同输入批次结果一致。
- 数据源失败不会使超过 1% 的候选错误迁移为 excluded。
- 快照清理后仍能重放当前 A/B 结论。
- `go test ./...`、`npm run build` 通过，总 Go 覆盖率不低于 80%。
- 在 Apple Silicon 8 核、16GB RAM、本地 SSD 的参考环境中，以至少 1,500 家预筛公司和 90 天快照执行 200 次、并发 5 的本地请求；页面首屏 API p95 小于 500ms，分页查询 p95 小于 800ms。
